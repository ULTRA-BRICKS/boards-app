# Cloud recovery release — 2026-09-15

## Reproduced failures
The initial page used the save-conflict screen when a connection failed before any edits. Repeated retries reused that network failure. Neon Data API had also exposed `public` although the intended RPC functions are in `prototype_api`. Its settings were corrected and read back, without grants on private tables.
A proposed external Vercel rewrite returned `INVALID_HOSTNAME` from the real auth endpoint. That deployment was not promoted to the public gamma domain. The replacement is a dependency-free Bun Function exposing four fixed operations, constructing fresh upstream headers instead of propagating a preview hostname/cookies.
An uncommitted earlier edit had removed `commit()`. It was restored from verified HEAD without reverting any newer changes. Oxc now checks undefined functions with the browser globals explicitly configured, and a mutation regression verifies this check rejects a missing editor callback.

## Corrected behavior
- Connection failure without edits says “Cannot connect to cloud”, with one Retry connection action.
- A real dirty draft retains export/retry/validated cloud-read choices. Cloud read happens before retiring the old draft and queue; the previous version remains available through Undo.
- A failed read cannot discard the draft. Repeated or ambiguous creation uses the same capability and versioned recovery rather than a replacement notebook.
- Every browser title ends with `| Boards`, including the separate font specimen.
- Browser diagnostics keep at most 120 allowlisted events and record operation/status/timing, never raw request data, edit keys, document text, cookies or tokens. The server relay logs the same limited operational facts.
- Public service-worker caching stays separate from all cloud operations. Both successful and failed relay responses have `no-store` headers; the relay is not an open proxy and has no privileged database credential.

## Evidence gates
The initial seven targeted scenarios were red before recovery. Nine targeted scenarios now pass in Chromium and WebKit, including failed cloud read retention and Undo. The existing 15 Chromium / 14 WebKit scenario groups also pass. WebKit fixture runs intentionally block service workers; they do not substitute for the live SW check.
Unit tests include proxy header isolation, arbitrary-target rejection, bounded body size, error redaction, rendering, drafts and the lint mutation gate. See current runner output rather than historical test counts.
Public deployment, its exact ID, unmocked cloud write/read, loading timings and screenshots must be recorded below only after execution. The authenticated full app, real provider integrations and whole-project coverage remain separate gates; this release fixes the prototype's actual load/save path.
