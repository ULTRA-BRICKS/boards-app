# Implementation review — 2026-09-10

## Scope and evidence

This is a code/behavior review, not a production security audit. The approved paper/ink visual direction is retained. Changes are split into commits on `work/review-20260910` and validated before promotion to main.

[Verified candidate 29922cc](https://git.hyperide.ai/ultrabricks/boards-app/actions/runs/34501918744): **92 Node tests, 27 native Chromium checks, 9 additional review regressions in Chromium, 7 native WebKit checks, eight in-memory FontTools instances and both application builds passed**. Downloaded source/evidence artifacts were checked against the SHA-256 digests returned by GitHub. The recovered remote source was compared to the local worktree; the only differences were equivalent workflow/package formatting.

Local Chromium cannot navigate to localhost in this sandbox. Local browser work used the explicitly labelled HTML/HTTP harness; the successful GitHub Actions runs use real HTTP navigation and cookies. WebKit uses a simulated touch viewport, not a physical iPhone. External OAuth/mail/image/ticket integration transports remain fixtures unless explicitly stated otherwise below.

## Findings fixed

| Finding | Failure | Change and regression coverage |
|---|---|---|
| UTF-8 split across HTTP chunks | Russian letters and emoji could be decoded into replacement characters before JSON parsing | Buffer bounded bytes, decode UTF-8 once with fatal validation; test every incoming byte as its own chunk |
| Invalid request shapes | JSON `null`, arrays or primitives reached object handlers | Reject non-object request payloads with 400; preserve byte-limit errors |
| Stale avatar approval | An old suggestion could overwrite a newer owner-uploaded photo | Canonical avatar revision; supersede competing proposals on owner change/approval; validate revision atomically |
| Duplicate profile requests | Repeated linking suggestions flooded the confirmation list | Coalesce same-author/provider/target requests; supersede replaced avatar proposals; support explicit rejection of linking suggestions |
| Disposed save queue | An in-flight request could notify or reschedule after sign-out/reconfiguration | Disposed queues cannot notify, retry or write again |
| Draft loss after a failed earlier save | Text still being edited was missing from backup/retry | Commit active text into the paused queue before presenting the error; browser verifies backup and successful retry contain the latest text |
| Lost assignee initials | Assigning Niko to an S/M item silently removed unresolved S | Shared helper consumes only explicit/resolved hints; original D/N/M mappings are preserved and S is not guessed |
| Late UI responses | A closed search/ticket/photo panel could receive a result or reopen | Dialog/workspace generation guards and connected-node checks |
| Private state after sign-out | Cached workspace/history could remain reachable through commands | Dispose sync and clear workspace, selection, people and cached views; browser verifies the command palette cannot reopen it |
| Photo import usability | Users had to edit raw JSON | Editable page/column/task fields, inclusion toggles, uncertainty warnings and explicit review consent before creating a new board |
| Long multiline previews | Many source newlines overflowed the fixed preview canvas | Reflow whitespace in a cloned preview projection; preserve the stored text |
| Similarity versus intent | A model treated enabling/disabling or adding/removing as near duplicates | Conservative leading-action/negation guard only for duplicate suggestions; normal search still retrieves related work |
| Weak lexical matches | Function words could add irrelevant BM25 weight | English/Russian stopwords removed from lexical scoring |
| Static deployment leakage | A font deploy could inherit the parent board project/environment | Stage outside the repository, explicit separate project, allowlisted CLI environment and no private upload files |
| False CLI success | A missing/killed process could be misreported | Explicit checks for spawn errors, signal termination and non-zero/null status |

These tests cover the reported failure modes, not every possible account, rendering, concurrent-edit or provider failure.

## Real semantic model evaluation

Unlike the provider fixture tests, this check downloads and runs actual model weights on the GitHub runner CPU. It does not send the private workspace to a model service.

- Model: `intfloat/multilingual-e5-base`, revision `d128750597153bb5987e10b1c3493a34e5a4502a`, 768 dimensions.
- Corpus: the 15 public seed tasks; 15 manually authored English/Russian queries, plus eight duplicate/nonduplicate examples.
- Text-only Recall@3: **6/15 (40%)**. Hybrid Recall@3: **13/15 (86.7%)**. Hybrid MRR@10: **0.8833**.
- Two opposite-action examples had raw cosine above 0.94. The action guard rejects both as duplicates while retaining ordinary related-search behavior.
- The eight labelled duplicate examples pass with the guard. This tiny hand-selected sample does **not** establish general precision/recall or make cosine a probability. The guard is a heuristic, not a language entailment model.
- Measured encoding time excludes model download/startup and the application's network/database round trips. Do not quote it as production request latency.

[Measured summary and artifact provenance](semantic-quality-summary.json) · [Real-model workflow and full report artifact](https://git.hyperide.ai/ultrabricks/boards-app/actions/runs/34500828958).

The hosted application still needs an embedding provider configured. A successful model evaluation is not an automatically connected deployment. Exact vector scans and the current small-corpus limits remain; pgvector/HNSW and a calibrated reranker are not claimed as implemented.

## Publishing without Git

The code does not require Git for deployment. `npm run deploy` uses Vercel CLI for the board. `npm run deploy:type` builds and deploys the separate static type site from an isolated temporary directory. `npm run deploy:type:neon` builds a self-contained Node 24 fetch handler and deploys it with Neon CLI, independently of GitHub and Vercel.

These commands require the operator's authenticated CLI sessions. The function's HTTP/build contract is tested; the authenticated deployment is not claimed as completed.

Actual connector attempts in this review:

1. Vercel deploy: the exposed zero-argument action is rejected by the backend for missing `name`, `target`, `files`.
2. Vercel static import: the available action rejects the public GitHub HTML URL because its backend accepts only `claudeusercontent.com` URLs.
3. Neon Functions: the existing branch was resolved and its function list was empty. The deployment action rejected a mounted ZIP path because its exposed field requires encoded bytes. No function/deployment was created by this attempt.

The public `visual-evidence/type-site.html` is a generated portable source HTML file, not a claimed production website. No public board URL, live email, real OAuth or paid model call is reported as successful.

Official deployment references: [Vercel CLI](https://vercel.com/docs/deployments/overview), [Neon Functions CLI/API](https://neon.com/docs/compute/functions/deploy).
